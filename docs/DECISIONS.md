## D3 · 只用课程下发的 636 行数据，不引入 NASA 原始全集
**决定**：主分析严格基于 `data/raw/battery_capacity.csv`。
**理由**：题目"数据说明"写死 636 行 4 个体；原始全集是 34 个电池 + 每循环电压/电流/温度曲线，能把特征工程做得更真，但需要下载 + 解析 .mat + 与题目数据说明不一致，9 天内风险过高。
**代价**：特征工程只能从容量时序本身构造，报告里必须诚实写明这是数据局限而非方法局限。

## D4 · EOL 阈值取 1.4 Ah 为基准
**决定**：主结论用 τ = 1.4 Ah（额定 2 Ah 的 70%，NASA 惯例），同时给 τ ∈ [1.25, 1.60] 的敏感性扫描。
**理由**：需要一个可引用的工程惯例作为主线，同时必须显式承认它的人为性 —— 这正是 I3 的价值所在。
**关键事实**：B0007 最低 1.4005 Ah @ 循环 166，距 1.4 只差 0.0005 Ah，因此在该阈值下是删失而非失效。

## D5 · 模型集：M1 线性 / M2 双指数 / M3 随机森林 / M4 趋势+GPR
**决定**：四模型对比。其中 M3 是**反例实验**，不是陪衬。
**理由**：题目要求"至少两种方法"。四个模型分别代表：能外推的参数基线、有物理形式的经验模型、不能外推的树模型、带后验方差的概率模型。M3 用来证明"树模型在寿命外推上结构性失效"，从而解释为什么最终选 M4。
**降级路径**：M2 若拟合不收敛，退回单指数并说明。

## D6 · 评测口径：LOBOCV + 时序划分，禁用随机 KFold
**决定**：留一电池交叉验证（4 折）+ 训练段/测试段时序划分。
**理由**：相邻循环的容量高度自相关，随机 KFold 会让测试集信息漏进训练集，分数虚高且不可信。这是会被扣分的隐性错误，主动规避并写进报告。
**代价**：LOBOCV 的实现比 `cross_val_score` 麻烦，需手写循环。

## D14 · 派生列改名并禁止作特征
**决定**：`soh` → `cap_over_rated`，`soh_vs_first` → `cap_over_first`，并在 docstring 与 README 明写"禁止作预测特征"。
**理由**：审查实测这两列是 `capacity_Ah` 的精确仿射变换（`cap_over_first × 首循环容量 = capacity`，最大残差 2.22e-16，相关系数 1.0）。当特征用会产出 R²≈1 的假结果。改名是为了让列名本身带警告色彩。
**额外发现**：四块电池的**首循环容量恰好都等于各自最大值**（1.8565 / 2.0353 / 1.8911 / 1.855），这层巧合会把「用 first 归一化」的泄漏彻底藏住——报告里必须写一句。
**部署前提**：`cap_over_first` 要求目标电池已有第 1 个循环的数据，现场问答会被问"预测时哪来的首循环容量"，需在报告中交代。

## D18 · 容量再生的解释降级为「假设」，并拆出共模成分

**决定**：不再断言"容量再生是锂电池的电化学现象（电解液再分布）"。改为四条：
1. 该机制**未经本数据验证**，只能作为假设；**共模成分的物理来源同样无法由本数据分辨**
   （可能是几块电池共同的实验/测量事件，也可能是别的），本项目只主张「存在共同成分」，不主张成因。
2. 跨电池同步性有硬证据：**同号率置换检验**（环形移位法现场估零基准）显示
   **三块同批之间 p=0.000**，而与 B0018 的全部 p>0.28（检不出耦合）。
   ⚠️ 零基准**不是 0.5**——两条序列各自都有强负漂移（P(Δ<0) 约 0.72–0.85），
   独立零基准约 0.59–0.73。第三轮审查抓到初稿把 0.5 当参照，把证据放大了约 2.5 倍。
3. 共模强度的正确读法：**四块口径 49.6%（零基准 1/k = 25%）**；
   **同批三块口径 82.4%（零基准 33.3%）**。不能只报一个百分比而不给零基准，
   也不能用含 B0018 的四块口径去代表「同步程度」——它被不相关的个体稀释了 33 个百分点。
4. 处理方式：把波动拆成「**共模 + 个体**」两部分，共模部分进不确定性分析的「数据不确定」层。

**口径修正**：`12` 是「电池×循环」对计数。同一循环上多块电池同时回升的，按**一个事件**合并后是
**9 个**（12 − 5 + 2）。⚠️ 这是**合并约定**，不是统计结果，报告里必须写明这条假设。
（本条初稿写「≤10」，第三轮审查指出与代码不一致，已改为精确的 9。）

**理由**：审查指出我给的机制叙述无引用、无验证，且与数据里的同步性直接冲突。
更现实的是——图上三条曲线在 x=90 同时鼓起，老师一眼就能看到并追问"为什么"。
带着一个答不上的因果解释去汇报，比诚实说"这是假设、我们发现了共模证据"风险大得多，
而后者反而正好落在评分表的「独立思考」上。

## D19 · 报百分比必须同时报零基准，报比较必须两边都算完

**起因**：到 W8 为止共 **7 次**同类错误——**数字是对的，论述是编的**
（初稿写「连续四次」，是没数清；第五轮审查 F6 指出与表格行数不符，已改为 7）。

| # | 我写的 | 实际 |
|---|---|---|
| 1 | 「IQR 会把晚期真实低容量误判成异常」 | IQR 标记 **0** 个 |
| 2 | README「B0018 同样未观测到失效」 | B0018 第 97 循环就跌破了 1.4 Ah |
| 3 | 「σ 主要被回升事件驱动」 | 置零回升点后 σ 只变 0–14% |
| 4 | 「共模占残差方差 49.6%」 | 零基准是 **1/k = 25%**；同批三块口径 82.4% |
| 5 | 「B0018 与共模 +0.348，弱正相关」 | 低于自身零基准（p=0.998），**读反了** |
| 6 | 「阈值下移影响更大，因为曲线凸」 | B0005 两侧相等、B0006 反向——**方向不统一** |
| 7 | 「这个倍数比模型误差大得多」 | **模型误差还没算** |

**决定**，三条硬规则：

1. **报任何百分比/占比，必须同时报零基准**。跨个体均值构造天然含 1/k 的自相关；
   相关分析的零基准逐个体不同（本数据 0.31–0.73，不是 0）。缺基准的百分比一律不进报告。
2. **凡「A 比 B 大 / A 是最大的」这类比较句，两边都必须是已经算出来的数字**。
   只算了一边就写比较，等于编造。（第 7 条就是犯了这个。）
3. **不为了圆一个叙述去找机制**。第 6 条用「曲线凸」解释一个方向不统一的现象，
   是先有结论再补理由，反过来做才是对的。

**机制保障**（不靠自觉）：所有给老师看的文字里，数字一律由 f-string 从 DataFrame 取值，
`` `outputs/tables/*.md` `` 全部标注「由代码生成，勿手工编辑」。我想编也编不进去——
本轮的 4 处错都发生在**代码里硬写的解释性定语**上，改完全部变成取值。

**代价**：每句话都要多写几个 f-string，代码变长；换来的是论述可被复现。

## D21 · `cycle` 有两种身份；特征必须是因果的；泄漏检测不能只扰动能值

**起因**：W8 要写特征，而 `preprocess.FEATURE_EXCLUDE` 里明写「`cycle` 不得作特征」。
可是 M1/M2/M4 的回归输入里**必须有 cycle**（它是时间轴）。两条规则直接冲突，
报告里会自相矛盾。

**决定**，把两件事分开命名，并写进代码与报告：

| | 任务 A：个体内轨迹外推（主线） | 任务 B：跨个体早期预测 |
|---|---|---|
| `cycle` 的角色 | **回归自变量（时间轴）**，必用 | **禁止作特征**（个体内时间不可迁移） |
| 谁用 | M1 / M2 / M4 | M3 随机森林（反例实验） |
| 样本量 | 每块电池一条曲线 | 名义 4 块，**可用标签 3 块** |

`FEATURE_EXCLUDE` 的禁令只约束任务 B。任务 A 里 `cycle` 不是「特征」而是 x 轴。

**第二条**：任务 B 的特征必须**因果**——第 t 行的特征只能用 t′ ≤ t 的数据。
本模块的落地方式是「**先截断到 cycle ≤ K，再算特征**」，所以只要这个顺序成立，
任何特征都碰不到未来数据（居中窗口也不例外）。

⚠️ 这里纠正 D21 的初稿：我一开始写「W5/W6 用居中滚动窗口，拿来当特征就是泄漏」——
**这个说法是错的**。每块电池只算一个特征向量、时刻固定在 t=K，
居中窗口在截断后的数据上最多用到第 K 行，没有越过 K。
居中窗口只有在「逐行给出 (cell, t) 特征且 t < K」的面板式设计里才是泄漏。
本模块仍用 trailing（`center=False`），但那是**保守选择**，不是硬要求。
（这条错误是**变异测试**抓出来的：我把 trailing 换成 center=True，
泄漏检测竟然照样通过——顺着这条追下去才发现叙述本身错了，检测没有错。）

**第三条（本次最重要的方法论）**：泄漏检测必须**三臂**，而不是「我保证没泄漏」。

| 臂 | 做法 | 只抓得到哪一类泄漏 |
|---|---|---|
| A 扰动臂 | 把 t>K 的**容量**随机扰动 ±0.5 Ah | 用了未来的**容量值** |
| B 删行臂 | 把 t>K 的行**整行删掉** | 用了未来行的**存在性/元数据**（行数、最大循环号…） |
| C 负控制 | 故意泄漏的对照列，必须被对应臂抓到 | 证明 A / B 有分辨力 |

**为什么必须有 B 臂**（第四轮独立审查 F1 亲自演示）：初版只有 A 臂，
审查往特征里塞了一列「全表行数」——扰动容量时它**一个数都不会变**，
于是顺利通过 A 臂、通过列名白名单，最后把 168 写进了报告表。
A 臂对元数据**结构性无感**，这不是实现疏忽，是那个实验设计本身就覆盖不到。

**为什么 C 必须走同一条管线**（同轮 F5）：初版负控制是自己另算两列、
**绕过** `build_features`，所以它只证明了「比较器有分辨力」，
证明不了「管线里的泄漏检测有分辨力」。现在对照列由
`build_features(..., extra=...)` 在**同一段返回路径**末端注入，
三条对照分别钉住「未来容量值 / 未来行是否存在 / 未来标签」三个通道。

**顺带记下的一条事实**：任务 B 名义上有 4 块电池，但 B0007 删失没有 EOL 标签，
**实际可用 n = 3**，df = 1，α=0.05 双侧的 |r| 临界值是 **0.997**；
而 n=3 时 Fisher z 的标准误 `1/√(n−3)` 分母为负、无定义，r 的 95% 置信区间是
**整个 [−1, 1]**，10 个特征的 p **全部 > 0.20**。
所以「哪个特征与寿命相关」在这里**完全不可推断**——「符号稳定 / 翻号」只能当描述，
不能当结论，更不能给噪声安上「窗口长度效应」这种机制（D19 第 3 条）。
W8 因此不做特征筛选，选哪些特征交给 W13 的 LOBOCV 判。

## D22 · M3 的位置：反例要「干净」，查表不许当预测

W10 写 M3（随机森林）时定下三条，都是为了保住这个反例的证明力。

**第一条：任务 A 的 M3 只吃一个自变量 `cycle`。**
它不是「一个还不错的模型」，它的作用是**证明树模型不能外推**。证据链有三层：
① 外推段预测严格是常数（极差 < 1e-12）；② 该常数必落在训练标签区间内
（分段常数模型的输出只能是训练标签的凸组合）；③ 树长到底
（`max_depth=None, min_samples_leaf=1, bootstrap=False`）时它**精确等于最后一个训练观测值**。
第二、三条只在「输入只有一个 x、模型只有树」时才是干净的结论；
一旦塞进 `cycle²` 之类的第二个特征，"没有趋势概念"这个解释说就不再唯一。
所以护栏放在**调用方**（`run()` 里查 `estimator.n_features_in_`），不是放在
`fit_rf` 自己内部——因为「fit_rf 被整个换掉」时内部断言是不会执行的，
这一点由 `scripts/mutation_test.py` 的 W10-M1 固定住。

**第二条：训练区间内被判为 EOL，一律标「查表」，且不得算作预测精度。**
切分点 M 一旦越过某块电池的真实寿命（本数据：M=100 越过 B0018 的 97），
训练段里就出现了容量 ≤ τ 的点，模型会"预测"出一个落在训练区间内的循环号，
误差看着小甚至恰好为 0。那不是外推，是查表。`run()` 里对此有断言
（备注必须带「查表」，W10-M3 固定），md 第七节也把两列并排放，逼读者一起看。

**第三条：去趋势实验的结论被降级（这是断言逼出来的，不是我一开始就想清楚的）。**
初版我写的断言是「去趋势后 R² 必须大于纯树」。它**失败了**：B0006 反而略差
（−2.23 → −2.29），B0018 差得更多（−2.41 → −6.21）。
追下去才发现「线性趋势 + 残差树」的外推形式是**「一条直线 + 一个常数平移」**，
那个平移可正可负、没有任何机制约束它；而 B0018 测试段自身标准差只有 0.0332 Ah，
几十毫安时的平移就足以让 R² 翻几倍。
所以正确的说法是：**去掉趋势之后，剩下的自由度必须被约束**——
不是「去趋势能救」。M1 的斜率由 80 个点外推、残差平移纯自由，两者都没有
「我有多不确定」的表达，这正是 M4 要用 GPR 的理由。
同时记一条读数纪律：**R² 在负值区对绝对误差极度敏感，不能拿 R² 的差值当改善幅度。**

（顺带：`EOL_SEARCH_MULTIPLE` 从 `models_parametric.py` 迁到 `config.py`，
因为 M2（求根）与 M3（扫描）都要在同一个搜索区间里判断「有没有穿越阈值」，
各写一份就是 W5/W6 的「两个模块各写一份 window=11」重演。）

## D23 · 三条被审查打出来的读数纪律（R6）

第六轮审查（W9+W10）里三条 high 全部属于同一个毛病：**数字算对了，但那个数字不属于那个论断**。
这里固化成规则，后面每一个模型、每一张表都按这个来。

**第一条：形状/单调性判据只能作用于「没有数据的区段」。**
M2 的「外推单调」原来在 `[1, 5N]` 上检查，把**训练段内**那点上翘也算进去了
（B0005 在 [1, 13.9] 内从 1.817 升到 1.834，峰值还在数据里），于是整块电池被判
"外推不可靠"、"不给寿命"。而实际上外推段严格递减、确实穿过 τ（第 107 / 115 循环）。
判据必须只测**真正外推的那一段**，否则它测的是拟合形状，不是外推风险。
连带教训：图上「在约第 400 循环处上翘」是 `argmin` 落在探针区间端点的假象——
**任何用 argmin/argmax 定位"拐点"的图注，都要先确认它不是端点。**

**第二条：「参数不可辨识」不等于「预测不可靠」。**
我原来想当然地把条件数 10^11 当成 M2 失败的原因。做了初值扫描才发现：
换 5 个起点，`a` 从 106 滑到 201、训练 RMSE 一位不差，而 **EOL 预测一个循环都不变**。
也就是说这条脊只影响参数解释，不影响预测。M2 的真问题是**系统性偏差**：
外推到观测末端时它把 1.325 Ah 说成 0.997 Ah，四块电池平均低 0.29 Ah。
**结论：要证伪一个模型，得拿出它错在哪（偏差/方差/形状），
不能拿一个"看起来病态"的指标顶替。**

**第三条：跨电池的平均 R² 不能用来排序，比误差就用 Ah / RMSE / 循环数。**
R² 的分母是**各自电池测试段的方差**，跨电池取平均没有意义，且在负值区对绝对误差极度敏感。
实测：趋势+树与 M1 的平均 R² 是 −1.73 vs −1.05（看起来更差），
而平均 RMSE 是 0.0834 vs 0.0840（其实略好）——**排序直接翻了**。
更细一层：RMSE 的均值也只能当参考，逐块看趋势+树只在 1/4 块电池上赢 M1。
所以 W13 的模型对比主表必须**逐块给数 + 只对同分母的量做比较**。

## D24 · M4 的结构：GP 不负责外推，带宽必须显式相加

写 M4（趋势 + GPR）时踩了两个坑，都写成了断言，防止以后重新踩。

**第一条：平稳核的 GP 在数据之外就是一条水平线。**
实测残差 GP 学到的长度尺度是 3.6–23 个循环，而外推距离是 52–88 个循环。
离开数据 5 倍长度尺度后，GP 后验均值降到 1e-8 Ah 量级（= 0），
GP 单独的标准差饱和成常数（0.022–0.035 Ah，随距离变化 < 1e-12）。
**所以「外推」这件事只能由趋势项承担**；想让 GP 自己外推得换非平稳核，
但那样「趋势不确定性」就被埋进超参，报告里说不清那条带子为什么那么宽。
本项目选择**显式两层相加**：`Var = 趋势参数方差(OLS) ⊕ 残差方差(GP)`。
这条由 `structure_checks()` 的五条断言钉住（含「5N 处趋势方差占比必须 > 50%」，
实测 70–81%），变异用例 W11-M1 把趋势方差去掉会当场失败。

**第二条：噪声下限不能交给 `WhiteKernel` 自由学。**
第一版那样写，WhiteKernel 把噪声学成 3.6e-9，于是 GP **逐点插值**了 80 个残差
（训练 RMSE 4.8e-10、训练 R² = 1.000）——过拟合，而且会让对比表出现
「M4 训练段完美」的假象。现在 `alpha` 固定为 OLS 残差方差（残差里至少含有观测噪声），
GP 只能去找「超过噪声的结构」；训练 RMSE 回到 0.010–0.020 Ah，与其他模型可比。
断言：训练 RMSE 不得小于残差噪声的 0.1 倍（变异 W11-M2 会触发）。

**顺带记一条如实上报的缺陷**：M4 的 EOL 90% 区间宽 12–40 循环，
而点估计误差就有 21 循环，**3 块有真值的电池只覆盖了 1 块**。
原因不是代码错，是第三层不确定性（「线性这条形式本身是否成立」）没进区间。
这条缺口不许藏，它就是 W14 与 W17 的入口。

## D25 · 第七轮审查（W11+W12）的五条教训

这一轮 2 high + 6 medium，全部属于同一类：**改了实现，没改对实现的描述**。
报告文件头写着「数字随代码重算」，但**描述性文字不会自动重算**。

**第一条：报告里对机制/配置的描述必须由代码生成，或者干脆不写。**
md 第 9 行写「核 = `C·RBF + WhiteKernel`，三个超参由边际似然学」，
而实现里根本没有 WhiteKernel——噪声是 `alpha=σ²_OLS` 写死的，只学 2 个超参。
这是把「上一版实现」的描述留在了「这一版报告」里。
现在核的写法直接从 `gp.kernel_` 取字符串、超参个数从 `len(kernel_.theta)` 取。

**第二条：文档字符串与注释里的数字同样会过期。**
`models_gpr.py` 文件头写「长度尺度只有 0.9–4.3 个循环」，md 第七条写「ℓ≈1–4」，
而真实值是 3.62–23.00（改核之前才是 1–4）。
**规矩：docstring/注释里不写数据相关的数字**，一律指向能现算的表。

**第三条：「常数」必须标定义域。**
「数据之外 GP 标准差是常数」只在**离开数据 5 倍长度尺度之后**成立；
在 `[M, 5N]` 整段上它从 0.009 长到 0.035 Ah。断言也分成两段写（远场常数 + 整段极差）。

**第四条：机制名字要对，不能安一个解释同时解释两个相反符号。**
旧文说「B0005/B0006 的真实衰减是加速的，直线必然偏」——但项目自己 W5 表里
B0006 的加速比是四块里最低的，而且两块电池的 EOL 误差是 +21 / −15。
现在改成两个可算的决定量：**切分点处的水平偏移** 与 **M 之后的实际斜率**，
并给出每块电池的这两个数（B0005 高 0.0535 Ah 占上风 → 报晚；B0006 斜率陡 2.1 倍 → 报早）。
同理，任务 B 里那个「近共线」也是错名——一个自变量谈不上共线，
正确说法是「斜率唯一确定，但被 1/Δx ≈ 667 放大」。

**第五条：合并 API 不许覆盖身份列。**
`to_common_schema` 原来无条件把「模型」列写成传入的名字，
M1/M2 共用一张表时会把 M2 的 4 行静默改标成 M1。
现在：不传名字就保留原列；传了名字则要求表内只有一个模型且与之一致，否则报错。
这条是为 W13 铺路——合并主表时**身份列丢了，后面所有比较都是错的**。
