# 决策记录（DECISIONS）

## D1 · 创新档位选 B（适当创新）
**决定**：基础四条任务完整覆盖，创新只叠加、不替换。拒绝 A 档（太浅）与 C 档（时间不够、偏离题目数据说明）。
**理由**：用户要求"B 是在完成老师说的那四条基本任务的基础上再进行的"。9 天到视频截止，C 档要下载几百 MB NASA 全集并解析 .mat，是时间黑洞。
**代价**：上限受限，"分析深度"一栏无法靠数据规模取胜，只能靠方法严谨性。

## D2 · 砍掉 I7（删失 + Weibull 生存分析）
**决定**：整项删除，不做生存分析。但**保留**"B0007 未跌破 1.4 Ah，寿命只能记为 >168（右删失）"这一数据事实，用一句话表述。
**理由**：用户明确表示该部分没学过、现场问答讲不好。评分表里"论证充分性"怕的不是结论弱，是不知道自己的结论弱；放一个自己讲不清的方法进去是负资产。
**连锁修改**：①三层不确定性的"数据不确定"改为=容量再生+残差噪声（不含删失）；②阈值扫描图把 B0007 画成"无穿越点"；③第 7 章寿命统计口径注明 B0007 不纳入均值。
**代价**：失去一个统计上更正确的亮点，换来现场问答不失分。

## D3 · 只用课程下发的 636 行数据，不引入 NASA 原始全集
**决定**：主分析严格基于 `data/raw/battery_capacity.csv`。
**理由**：题目"数据说明"写死 636 行 4 个体；原始全集是 34 个电池 + 每循环电压/电流/温度曲线，能把特征工程做得更真，但需要下载 + 解析 .mat + 与题目数据说明不一致，9 天内风险过高。
**代价**：特征工程只能从容量时序本身构造，报告里必须诚实写明这是数据局限而非方法局限。

## D4 · EOL 阈值取 1.4 Ah 为基准
**决定**：主结论用 τ = 1.4 Ah（额定 2 Ah 的 70%，NASA 惯例），同时给 τ ∈ [1.25, 1.60] 的敏感性扫描。
**理由**：需要一个可引用的工程惯例作为主线，同时必须显式承认它的人为性 —— 这正是 I3 的价值所在。
**关键事实**：B0007 最低 1.4005 Ah @ 循环 166，距 1.4 只差 0.0005 Ah，因此在该阈值下是删失而非失效。

## D5 · 模型集：M1 线性 / M2 双指数 / M3 随机森林 / M4 趋势+GPR
**决定**：四模型对比。其中 M3 是**反例实验**，不是陪衬。
**理由**：题目要求"至少两种方法"。四个模型分别代表：能外推的参数基线、有物理形式的经验模型、不能外推的树模型、带后验方差的概率模型。M3 用来证明"树模型在寿命外推上结构性失效"，从而解释为什么最终选 M4。
**降级路径**：M2 若拟合不收敛，退回单指数并说明。

## D6 · 评测口径：LOBOCV + 时序划分，禁用随机 KFold
**决定**：留一电池交叉验证（4 折）+ 训练段/测试段时序划分。
**理由**：相邻循环的容量高度自相关，随机 KFold 会让测试集信息漏进训练集，分数虚高且不可信。这是会被扣分的隐性错误，主动规避并写进报告。
**代价**：LOBOCV 的实现比 `cross_val_score` 麻烦，需手写循环。

## D7 · 报告用 python-docx 直接生成
**决定**：按课程模板 9 章生成 `.docx`，图表由代码产出后插入。
**理由**：用户选 (a)。手工搬运图表会有图号/表号错乱风险，且浪费时间。
**已知限制**：Word 的目录是 TOC 域，生成后需用户在 Word 里 `Ctrl+A` → `F9` 更新一次页码。这一点必须写进交付说明。

## D8 · git 身份用 GitHub noreply 邮箱
**决定**：`user.name = Tony-Stank-shift`，`user.email = 279204584+Tony-Stank-shift@users.noreply.github.com`，**仅 repo 局部配置**。
**理由**：公开仓库上每个 commit 的邮箱都会永久公开并被爬虫抓取。noreply 邮箱同样能把提交归属到用户账号，且不暴露真实邮箱。用 `--local` 不动用户的全局配置。

## D9 · 汇报视频只出声 + 录屏
**决定**：用户本人录屏配音，我交付 8–10 页 PPT + 卡到 4:40 的逐字稿 + 演示脚本。
**理由**：5 分钟视频 = 播放 5 分钟 + 现场问答 3 分钟，超时是硬伤。逐字稿能保证节奏。

## D10 · 项目规则：「讲不出来就不进报告」
**决定**：每个保留的创新点都附 30 秒口语版说明；用户录视频前逐条过一遍，讲不清的砍掉。
**理由**：用户砍 I7 的真实判据是这个。这比"这个创新点值不值"更贴近实际约束（现场 3 分钟问答）。

## D11 · 第三方审查按阶段做，不是每小项
**决定**：自检 + 汇报卡每小项都做；独立第三方审查按阶段做 5 次，另加 W14（模型对比主表）与 W21（报告成稿）两个关键节点。
**理由**：25 项 × 1 次审查 = 时间黑洞，会挤掉真正的分析工作。
**代价**：个别小项的错误可能晚一个阶段才被发现 —— 用每小项的自检来补偿。

## D12 · 反对外部审查：什么算"创新"必须能落地成数字
**决定**：每个创新点的验收判据必须是**一个可复现的数字或图表**，不接受"我们讨论了……"这种表述。
**理由**：评分表"论证充分性与独立思考、创新性"最容易变成空话。数字是可以被追问的，形容词不行。
