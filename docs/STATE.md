### ① 对抗输入测试（新脚本 `scripts/adversarial_test.py`，43 条，全过）

与 `mutation_test.py` 分工不同：那个注入**代码错误**（改坏实现），这个注入**数据错误**
（NaN / inf / 空数组 / 常数 / 严格递增 / 单点 / 行数不足或超出）。
判据是：**要么给出可手算的正确答案，要么明确报错**；「静默算出一个数」是最坏结果。

它抓到 **3 个静默错误**（都在已提交的代码里）：

| # | 位置 | 病态输入 | 修补前（错） | 修补后 |
|---|---|---|---|---|
| 1 | `sensitivity.prefix_min_mask` | 容量含 NaN | NaN 污染 `minimum.accumulate` → 之后全不算「新低」→ `eol_at_exact` **静默返回「删失」**。实测 cap=[1.8,nan,1.7,1.6,1.5]、τ=1.6 正确答案是第 4 循环，旧代码返回 None | 显式 `ValueError` |
| 2 | `features.build_features_one` | 容量含 NaN | 静默产出 NaN 特征；而泄漏检测用 `equal_nan=True` 比较，**NaN==NaN 被判成「没变化」**，检测也发现不了 | 显式 `ValueError` |
| 3 | `features.build_features_one` | 只给 30 行却传 K=50 | 照常返回一组数，但那是 **K=30 的特征**，表头却写着 K=50 | 要求「恰好覆盖到第 K 循环」，否则报错 |

教训：**报错比返回错答案好，但最怕的是两者都不做。** 上面三处都不崩溃，
只是悄悄给了一个能被下游当真使用的数——这种错误只有主动喂病态数据才会暴露。

## 环境坑（重要，别重复踩）

1. **DSH 沙箱禁止 chmod**。`pip install` 与 `python -m venv` 都要在临时目录做 chmod + rmtree，被拒即失败。**解法**：装包用一次性 `sandbox_permissions=danger-full-access`。项目因此不用虚拟环境。
2. **`curl.exe` 在沙箱里跑不通**，返回 HTTP 000 且极快——**测量假象**，不是网络不通。测网络用 Python 的 `urllib.request`。
3. **中文输出乱码**：`chcp 65001` + `PYTHONIOENCODING=utf-8` 后正常。审查指出"GBK 码页导致"这个机制描述**存疑**，已降级为"待复现"。
4. **matplotlib 字体缓存**默认写到工作区外（只读）。已在 `config.py` import 期设置 `MPLCONFIGDIR`。
5. **git 推送必须用 openssl 后端**（已 `git config --local` 设好）：
   - 默认 schannel + 代理 → `AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS`
   - 绕过代理直连 → `Connection was reset`（被阻断）
   - **`http.sslBackend=openssl` + 保留全局代理 → 读操作成功**（`ls-remote` 退出码 0）
6. **git push 必须提权**：沙箱禁止创建命名管道，凭据管理器起不来
   （`sh.exe: fatal error - couldn't create signal pipe, Win32 error 5`）。
   用一次性 `sandbox_permissions=danger-full-access` 后推送成功。
   **每次 push 都要这样，属于既定代价。**
7. **PowerShell 的 `Get-Content` 默认按 GBK 读文件**，会把 UTF-8 的中文显示成乱码。
   那是显示问题，不是文件问题——核对文件内容请用 Python 按 `encoding="utf-8"` 读，或 `Get-Content -Encoding UTF8`。

**这一块的方法论贡献**（报告里比数字更值钱）：

1. **`N_EOL(τ)` 是阶梯函数，只在「创下新低」的循环上取值**，所以整条曲线被前缀最小点集
   精确决定；网格扫描会丢分辨率。本模块用断点集画图，另用朴素扫描做交叉验证
   （141 个 τ × 4 块 = 564 次比对，0 处不一致）。注意这两个算法**共用** `is_at_eol`，
   所以这条交叉验证证明的是「前缀最小捷径」没算错，**不负责**验证 `≤` 口径（那是断言 6 的活）。
2. **「±X 循环」不说窗口就是没说完**——极差随窗口宽度单调变大（±0.005 → ±0.1 时从 2 → 63）。
   这是 W5 那条「加速比依赖切分点 h」的第二次出现，同一类教训。
3. **两侧不保证对称，且方向不统一**：B0005 两侧相等；B0006 是「阈值上调对寿命的削减」
   更大（τ↑ 时寿命 −22 vs τ↓ 时 +17）；B0018 是「阈值下调带来的寿命增益」更大
   （τ↓ 时 +23 vs τ↑ 时 −17）。所以**不主张任何单一方向的不对称**。
