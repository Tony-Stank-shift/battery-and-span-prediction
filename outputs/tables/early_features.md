# 早期特征与未来信息泄漏证明（W8）

> 本文件由 `src/features.py` 自动生成，数字随代码重算，**不要手工编辑**。

## 一、先分清两个任务

本项目里「预测」有两种口径，特征规则完全不同：

| | 任务 A：个体内轨迹外推（主线） | 任务 B：跨个体早期预测（本节） |
|---|---|---|
| 做法 | 用前 M 个循环拟合，外推后面的容量 / RUL | 用前 K 个循环的统计量，预测寿命 |
| `cycle` | **回归自变量（时间轴）**，必用 | **禁止作特征**（个体内时间，跨个体不可迁移） |
| 谁用 | M1 / M2 / M4 | M3 随机森林（反例实验） |
| 样本量 | 每块电池一条曲线 | **名义 4 块，可用标签 3 块** |

`preprocess.FEATURE_EXCLUDE` 里「`cycle` 不得作特征」那条针对的是**任务 B**；任务 A 里 `cycle` 是 x 轴而不是特征。这两句必须同时写，否则报告里「禁止用 cycle」和「模型输入含 cycle」会互相打脸。

⚠️ 我原来在这里写的机制是**编的**（第四轮审查 F2 逐条否证）：「前 50 个循环容量几乎还没开始掉」——不成立，特征表里 `drop_ratio_to_K` 显示 B0006 已掉 12.75%、B0018 已掉 10.47%；「b 接近 0」——也不成立，B0006/B0018 的 b 分别是 −0.607 和 −0.930，离 0 有 414 / 850 个标准误；「差了两个数量级」——按端点绝对值算只有 22.5 倍。**结论（不稳、不作主力）保留，但理由必须换成上面这张 K 剖面表。**W13 里它只作「形状」的辅助说明。

## 三、泄漏证明：两条正实验 + 一条带对照的负控制

**正实验 A（扰动臂）**：把 t > K 的 436 行容量随机扰动 ±0.5 Ah（额定的 ±25%），重算全部特征。

**正实验 B（删行臂）**：把 t > K 的 436 行**整行删掉**，重算全部特征。

两臂都必须让 10 个特征 × 4 块电池**逐个完全相同**（`rtol=0, atol=0` 严格判等）。

⚠️ **为什么必须有第二臂**（第四轮审查 F1）：初版只有扰动臂，而它只能发现「用了未来的**容量值**」。如果某列用的是「未来**行是否存在**」这类元数据（行数、最大循环号……），扰动容量时它**一个数都不会变**——审查据此造了一个 `n_cycles = len(全表)` 的变异，它顺利通过扰动臂、通过列名白名单，最后把 168 写进了本文件。删行臂就是专门堵这个洞的。

**负控制**（三条，分别对应三种泄漏通道，且**都走 `build_features` 的 `extra` 钩子**，与真实特征共享同一段返回路径）：

| 对照特征 | 通道 | 被哪一臂抓到 |
|---|---|---|
| `LEAK_cap_min_full` | 未来容量值 | 扰动臂、删行臂 |
| `LEAK_n_cycles_full` | 未来行是否存在 | 删行臂 |
| `LEAK_eol_cycle_full` | 未来标签 | 扰动臂、删行臂 |

三条**全部被抓到**，且两臂各自都至少抓到一条 → 检测有分辨力，不是空转。

（初版的负控制是自己另外算两列、**绕过** `build_features`，所以它只证明了「比较器有分辨力」，证明不了「管线里的泄漏检测有分辨力」——这是审查 F5。现在对照列由 `build_features(..., extra=...)` 在管线末端注入。）

只做正实验、不做负控制的检测，等价于「我保证没泄漏」——这句话在报告里没有价值，能被复现的断言才有。

顺带纠正一个我一开始写错的说法：**居中滚动窗口在本设计里并不构成泄漏。**因为每块电池只算**一个**特征向量、时刻固定在 t = 50，输入已截断到 cycle ≤ 50——居中窗口在第 t 行最多用到第 50 行，没有越过。只有「逐行给出 (cell, t) 特征且 t 可以小于 K」的面板式设计，居中窗口才会看到未来。本模块用 trailing（`center=False`）是**保守选择**：让「只依赖 ≤ 当前时刻」在代码形态上一目了然，代价是残差估计方差略大。

## 四、与 EOL 的相关：如实列出，并说明它没有推断意义

先把样本量说清楚：名义上有 4 块电池，但 **B0007 在 τ=1.4 Ah 下删失**（观察期内没到达 EOL），它没有 `eol_cycle`，所以下面每一行的 **n 都只有 3**。这不是可以「补一个寿命」凑成 4 的——把删失记成观测长度会系统性低估寿命（D2 已禁止）。

**n = 3，df = 1，α = 0.05 双侧的临界 |r| = 0.997。**也就是说，3 个点必须几乎完全单调才「显著」，而那不是「有关联」，那是**几个排序值的巧合**（W5 已被这个坑咬过一次：σ 最大的两块恰好是再生最多的两块，p≈0.08）。

本表里达到这个门槛的特征有 **0 个**。**即使有，也不作为筛选依据**——理由不是「我们不信任统计」，而是 n=3 时任何基于相关的选择都无法与事后挑选区分开。

⚠️ **n = 3 时，这一整节的符号比较都不能当证据用**（第四轮审查 F4）：
10 个特征的 p 值**全部 > 0.20**（最小的也有 0.20）；而 n=3 时 Fisher z 的标准误 `1/√(n−3)` 分母为负、根本无定义，r 的 95% 置信区间是**整个 [−1, 1]**。
所以下面这两行只是**描述**，不是「哪些特征可信」的结论：

- 符号未变：`cap_first`、`cap_at_K`、`drop_ratio_to_K`、`slope_to_K_Ah_per_100`、`linear_r2_to_K`、`n_regen_to_K`、`max_regen_to_K`；
- 符号变过：`slope_tail20_Ah_per_100`、`curvature_to_K`、`resid_std_trailing`。

而且「变号」里混着**近零值**（`resid_std_trailing` 在 K=30 是 0.032、K=40 是 −0.026），把一个几乎为 0 的相关系数从正变负叫作「窗口长度的效应」，是**给噪声安机制**——这正是 D19 第 3 条禁止的事。所以本节**不下**这类结论。

另一处口径提醒：K=20 时 `slope_tail20_Ah_per_100` 与 `slope_to_K_Ah_per_100` 是**同一个量**（20 个点的「末尾 20」就是全部），所以 K=20 那一列的两个相关系数必然相同（都是 0.640），不是两条独立证据。

## 六、这一节刻意没做的事

- **没有做特征筛选**：有效样本只有 3 个，筛选等于挑好看的结果。选哪些特征交给 W13 的 LOBOCV 判。
- **没有画散点图**：3 个点的散点图只会让人以为看到了规律。
- **没有用 `cell_censored` / `cap_min` / `eol_cycle` 这类整轨迹量**：它们是标签或标签的变形，W3 已登记在 `PROFILE_EXCLUDE`。
